# Offline SGP4 replay

Run `python replay.py` with the staged `input.tle` and installed OEL. The requested elapsed minutes are passed directly to SGP4, with no civil-time conversion, frame transformation, or gravity-constant overrides. The CSV contains native TEME position in km and velocity in km/s at 0, 360, ..., 4320 minutes. Python's float serialization preserves binary64 values on read-back.

The program pins the input text, enables checksum validation, checks the selected model and every propagation status, and repeats the grid in reverse order. It independently estimates velocity from the position samples at ±1 second and checks sensitivity using ±2 seconds. The 0.002 km/s limit is a kinematic sanity check, not a reference accuracy specification: it is intended to detect time-unit, scaling, or state-component mistakes without assuming that SGP4 velocity is exactly the derivative of its approximate position. The finite-difference checks use off-grid points, including one just before epoch, but those points are not exported. CSV format and numeric round-trip fidelity are checked before publishing `states.csv`.

The installed OEL 1.1.0 API reports `OGP-SGP4` for the near-Earth branch and uses `error is None` for success. Both backends are selected explicitly. The CSV is produced from the Python backend; the compiled Rust path separately propagates the same parsed TLE at all 13 epochs. The script reports the maximum Euclidean position and velocity differences and their epochs, with diagnostic agreement limits of 1e-5 km and 1e-8 km/s. These limits test numerical agreement between code paths, not physical orbit accuracy. A discrepancy is reported without replacing or suppressing the Python trajectory. The paths share OEL's parser and could share conventions or defects; neither their agreement nor the internal checks establish agreement with the withheld vectors. No reference vectors are used.
